# GE Chat รุ่นทดลองส่วนตัว

ขอบเขต: บางเขนเท่านั้น เพิ่มหน้า `/chat` ร่วมกับ timetable/account เดิม ไม่ใช้ enrollments.xlsx และไม่ทำ KU SSO หรือการลงทะเบียนจริง รุ่นนี้ไม่วิเคราะห์ประวัติการเรียน

## ทดลอง

เปิด `./run-local.command --keyword-only` เข้า GE Chat แล้วลอง:

- `ค้นหา 01001317` → `ว่างวันพฤหัส 13:00-18:00`
- `เริ่มใหม่` → `สนใจภาษา` → `เฉพาะวันศุกร์ 09:00-16:00`
- `เริ่มใหม่` → `สมรรถนะ 67 ด้าน 4` → `ภาคปกติ`

ตัวกรองในแผงซ้ายสะท้อนเงื่อนไขที่ตีความได้ ตรวจและแก้ได้ก่อนค้นหา ทุกคาบของหมู่ต้องอยู่ในวัน/ช่วงเวลาที่กำหนด หมู่เวลาไม่ครบยังดูได้ แต่เพิ่มไม่ได้ หมู่เต็ม ไม่เปิดสอน ประเภทภาคไม่ตรง หรือเวลาชน จะไม่ให้เพิ่มจากผลแชท โดยสถานะจำลองมีผลเฉพาะการทดลองวางแผนผ่าน Chat ไม่ใช่กฎลงทะเบียนทางการ

ประวัติสนทนาสูงสุด 20 ข้อความอยู่ในหน่วยความจำของหน้าปัจจุบันและจะเริ่มใหม่เมื่อออกจากหน้า ส่วนตารางบันทึกด้วยระบบเดิม ตัว Chat ส่งเฉพาะ structured filters และรายการอ้างอิงตารางไป backend; เมื่อใช้ Ollama ส่งข้อความล่าสุดกับตัวกรองเดิมให้โมเดลในเครื่อง ไม่ส่งประวัตินักศึกษา/บัญชี/ตารางให้โมเดล

## AI ที่ไม่เสียค่า API

ค่าเริ่มต้น `local-rules` เป็น parser ตามกฎ รองรับหัวข้อพื้นฐานและคำสั่งตัวอย่าง ไม่ใช่ generative AI ภาษาทั่วไป หากต้องการ LLM ใช้ Ollama ที่ติดตั้งและมีโมเดลบนเครื่องแล้ว:

```bash
CHAT_OLLAMA_MODEL=ชื่อโมเดลที่ติดตั้ง ./run-local.command --keyword-only
```

โมเดลทำหน้าที่แปลงภาษาธรรมชาติเป็น `ChatState` เท่านั้น ข้อเท็จจริงและผลค้นหามาจาก catalog/GE overlay ผ่านกฎฝั่ง server โมเดลไม่มีสิทธิ์สร้างรายวิชา กำหนดที่นั่ง หรือเพิ่มตารางเอง หาก endpoint ใช้งานไม่ได้หรือ JSON ผิด schema ให้ fallback ภายใน 15 วินาที ป้ายโหมดในหน้าเว็บบอกว่าใช้ Ollama หรือตัวช่วยตามกฎ ยังไม่ได้ติดตั้งหรือทดสอบกับโมเดล Ollama จริงบนเครื่องนี้ (ทดสอบ HTTP success/failure ด้วย fixture แล้ว)

## แหล่งข้อมูล

- `catalog.json.gz`: รายวิชา/คำอธิบาย/หน่วยกิต/หมู่/เวลา/ความจุและยอดลงทะเบียนจาก KU Drive ที่ผู้ใช้ให้ ตรวจไฟล์ต้นทาง 24 ต.ค. 2569 ว่าตรงกับ SHA-256 ใน metadata ทั้ง subjects/sections/schedules ไม่มีปีและเทอม
- `gened.json`: overlay แยกต่างหาก ทั้ง GE และการเปิดสอนเป็น mock มี source `demo://gened-regis` ปีและเทอม null ห้ามตีความว่าเป็นเทอมปัจจุบัน
- จำนวนที่นั่ง `snapshot_remaining` คำนวณจาก snapshot และไม่ใช่ตัวเลข realtime จำนวน `offering.remaining` แยก source/status ต่างหาก
- สิทธิ์มีเพียง `unknown`, `program_matches`, `program_mismatch` ประเภทภาคตรงไม่เท่ากับมีสิทธิ์ ต้องรอหลักสูตร/ชั้นปี/โควตา/วิชาบังคับก่อนและข้อมูลโปรไฟล์จริง
- ไม่ใช้ suffix `-64`/`-67` ของรหัสวิชาเป็นเกณฑ์ตัดสินรูปแบบ GE; ใช้ mapping ใน overlay เท่านั้น

## แทนด้วย export จริง

เตรียม JSON ที่ normalize แล้วตาม `GEExport` ใน `backend/chat.py` เมื่อได้ export จริงจะต้องแปลงคอลัมน์จากไฟล์ต้นทางเป็นโครงสร้างนี้ ไม่รองรับการนำเข้าไฟล์ Excel รูปแบบที่ยังไม่ทราบโดยอัตโนมัติ:

```json
{
  "dataset_version": "ต้องตรง metadata ของ catalog.json.gz",
  "source_url": "https://แหล่งข้อมูลจริง",
  "updated_at": "เวลาจัดทำ export",
  "academic_year": null,
  "semester": null,
  "courses": [{
    "subject_code": "01001317-67",
    "groups": ["พลเมืองไทยและพลเมืองโลก"],
    "competencies": [1, 2, 4, 5, 7, 8],
    "status": "mock"
  }],
  "offerings": [{
    "subject_code": "01001317-67",
    "section_id": "334131",
    "offered": null,
    "remaining": null,
    "programs": [],
    "eligibility_note": "ยังไม่มีเงื่อนไขจริง",
    "status": "mock"
  }]
}
```

เปลี่ยน status เป็น `verified` เฉพาะรายการที่ตรวจสอบกับแหล่งข้อมูลจริงแล้ว ใส่ปี/เทอมเมื่อมีหลักฐาน โปรแกรม `regular`/`special` หมายถึงประเภทภาคที่เปิดให้ ไม่เดาจากเลขหมู่ ข้อมูลที่ยังไม่ทราบให้ null/ว่าง แยก mock ไว้ได้ทีละรายการ อย่าติด verified ให้ข้อมูลที่เดาหรือคัดลอกจากตัวอย่าง

```bash
.venv/bin/python backend/import_ge_data.py /path/to/normalized-export.json
```

ตรวจ schema, รหัสวิชาเต็ม, section_id, คู่ซ้ำ และ dataset version ก่อนเขียนแบบ atomic ไฟล์ผิดจะไม่ทับของเดิม รีสตาร์ท backend เพื่อโหลดข้อมูลใหม่ หรือกำหนด `GE_DATA_PATH` ชี้ไฟล์อื่น หาก catalog เปลี่ยนจน version ไม่ตรง Chat จะหยุดให้บริการพร้อมข้อความชี้แจง ระบบค้นหาเดิมยังใช้ได้

สร้าง mock กลับมาได้ด้วย `.venv/bin/python backend/create_ge_demo.py` ซึ่งเขียน overlay เท่านั้น ไม่แก้ catalog

## การตรวจสอบ

Backend tests ครอบคลุม context/รีเซ็ต, สลับกลุ่มสาระกับสมรรถนะ, ทุกคาบต้องตรงเวลาว่าง, บางเขน, mock/unknown ไม่กลายเป็นสิทธิ์ยืนยัน, ที่นั่งเต็ม/ไม่เปิด/ภาคไม่ตรง, เวลาชน, stale snapshot, invalid refs, Ollama validation/fallback, atomic import และ identity validation

Frontend tests ครอบคลุมการถามต่อพร้อมส่ง state, ป้าย mock, แชร์ตารางและการบันทึกเดิม และส่งซ้ำได้เมื่อ network ล้มเหลว รวม regression tests เดิม

ผลตรวจ 24 ต.ค. 2569: backend 45 tests ผ่าน, frontend 9 tests ผ่าน, Ruff/ESLint ผ่าน, production build ผ่าน ตรวจหน้า `/chat` ใน browser จริงด้วย KU Drive snapshot แล้ว คำถาม `สนใจภาษา` คืน 20 รายการ (แสดง 8 รายการ) และ `ค้นหา 01001317` คืน 4 เวอร์ชันของรหัสวิชา พร้อมหมู่/เวลาและป้ายจำลอง ไม่ได้ทดสอบกับ MY.KU realtime หรือโมเดล Ollama จริง
