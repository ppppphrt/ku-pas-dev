# Chat GE: LLM + course retrieval

หน้าแรก `/` เปิด Chat GE โดยตรง ส่วน `/courses` คือ Course Discovery และ `/chat` ยังเป็นทางเข้าเดิมได้

## เปิดใช้ LLM

เลือก **Typhoon** ตามความต้องการของผู้ใช้แล้ว เตรียม `backend/chat.local.toml` (ไม่เข้า Git และกำหนดสิทธิ์ไฟล์ 600) ให้ใส่ `api_key` และ `model` ที่ใช้งานได้ ระบบอ่านไฟล์นี้อัตโนมัติโดยไม่ต้อง export ตัวแปร แล้วเปิด `./run-chat.command` ได้เลย ไม่ต้องส่ง key ในแชท

ไฟล์ตัวอย่างที่แชร์ได้คือ `backend/chat.local.example.toml` ตัวแปร environment มีลำดับก่อนค่าในไฟล์ `.env` ไม่ถูกโหลดอัตโนมัติ สำหรับ deployment ใช้ environment secrets ของโฮสต์ ไม่แนบไฟล์ `chat.local.toml`

หรือเลือกตั้งค่าแบบ environment ก่อนรันจากรากโปรเจกต์:

Ollama บนเครื่อง ต้องติดตั้งและเปิดโมเดลที่รองรับภาษาไทยก่อน:

```sh
export CHAT_OLLAMA_MODEL='your-installed-model'
./run-local.command --keyword-only
```

Hosted provider ใช้ API แบบ Chat Completions ตามแนวทางใน `ChatBot.zip`:

```sh
export LLM_API_KEY='your-api-key'
export LLM_MODEL='your-provider-model-id'
export LLM_BASE_URL='https://api.opentyphoon.ai/v1'
./run-local.command --keyword-only
```

เลือก model ID ที่บัญชีของคุณใช้งานได้ตาม [เอกสาร Typhoon](https://docs.opentyphoon.ai/en/api-reference/) ไม่กำหนดโมเดลตายตัวที่อาจเลิกให้บริการ Hosted provider มีลำดับก่อน Ollama หากตั้งค่าทั้งคู่ เก็บ key เฉพาะฝั่ง backend ห้ามใส่ตัวแปร `VITE_` หรือ commit secret ค่า endpoint ต้องเป็น HTTPS

`--keyword-only` ปิดเฉพาะโมเดล embeddings ไม่ปิด LLM ถ้าต้องการ hybrid vector/keyword ให้เปิดโดยไม่ใช้ flag นี้ และติดตั้ง dependencies ใน `backend/requirements-ai.txt` การสร้าง embeddings ครั้งแรกอาจต้องดาวน์โหลดโมเดลและใช้เวลา

Vercel: ตั้ง environment variables เดียวกันใน backend ของ deployment แล้ว redeploy หน้าเว็บไม่ต้องมี key และไม่ต้องเพิ่ม dependencies สำหรับ hosted LLM

## สิ่งที่เปลี่ยน

### ทวนความเข้าใจก่อนตอบ

คำตอบค้นหาและอธิบายรายวิชาจะเริ่มด้วยการทวนเงื่อนไขที่ระบบใช้จริง เช่น
“ผมเข้าใจว่าคุณต้องการค้นหารายวิชาในแค็ตตาล็อกบางเขน เกี่ยวกับ ‘อังกฤษ’
วันศุกร์ ช่วง 12:00–17:00 ใช่ไหมครับ? หากเข้าใจคลาดเคลื่อน พิมพ์แก้ได้เลยครับ”
แล้วแสดงคำตอบต่อในข้อความเดียว ผู้ใช้จึงแก้ความเข้าใจได้โดยไม่ต้องยืนยันทุกครั้งก่อนเห็นผล

ข้อความทวนสร้างจาก state หลังตีความ รวมเงื่อนไขที่คงไว้จากข้อความก่อนหน้า
ใช้ได้ทั้งภาษาไทย/อังกฤษ โหมด LLM โหมดสำรอง และกรณีไม่พบผลลัพธ์ โดยไม่เพิ่มการเรียก LLM
เมื่อเริ่มใหม่จะทวนเฉพาะเงื่อนไขใหม่ ส่วน intent ทักทาย/ขอข้อมูลเพิ่มและช่วงเวลาที่ไม่ถูกต้อง
ยังใช้ข้อความเฉพาะของขั้นตอนนั้น ข้อความทวนเป็นการแสดงความเข้าใจของระบบ ไม่ใช่การยืนยันสิทธิ์ลงทะเบียน

1. ส่งบริบทสนทนาและตัวกรองปัจจุบันไปให้ LLM แยก intent และสร้าง state ที่ผ่าน Pydantic validation รองรับการถามต่อ เปลี่ยนใจ ทักทาย และขอคำชี้แจง โดยไม่ยึดคำสำคัญอย่างเดียว
2. ค้นหาจาก catalog บางเขนทั้งหมด หาก semantic พร้อมจะใช้ embeddings ร่วมกับ keyword (threshold 0.35) รวมวิชาที่ไม่มีใน GE export โดยแสดงสถานะ GE ว่ายังไม่ยืนยัน เลือกเฉพาะ GE ยืนยันได้ เงื่อนไขเวลา หน่วยกิต และเวลาชนยังตรวจด้วยโค้ดเดิม
3. ส่งข้อมูลอ้างอิงเฉพาะผลค้นหาให้ LLM เรียบเรียงคำตอบไทย/อังกฤษ พร้อมสถานะข้อมูลจำลองและข้อจำกัด ไม่อนุญาตให้ LLM เพิ่มตารางหรือสร้างข้อมูลหมู่เรียนเอง
4. ตรวจ schema และรหัสวิชาที่อ้างในคำตอบ หากไม่ผ่านหรือ provider ล้มเหลว แสดงคำตอบสำรองและป้ายสถานะ LLM ไม่พร้อม ตารางและผลค้นหายังใช้งานได้
5. หน้าแชทยังคงตำแหน่งอ่านบทสนทนาและมีปุ่มไปดูผลลัพธ์ แทนการย้าย focus ไปผลค้นหาทุกครั้ง ข้อความที่ LLM สร้างแสดงตามต้นฉบับ ไม่ถูกส่งผ่านตัวแปล UI จนบรรทัดหาย

## แหล่งข้อมูลและขอบเขต

ตรวจรายการใน [KU Drive](https://kudrive.ku.ac.th/index.php/s/s8ccWBcJLGAGDaT) วันที่ 3 พ.ย. 2569 พบ `subjects.xlsx`, `sections.xlsx`, `schedules.xlsx`, `enrollments.xlsx` ยังไม่พบไฟล์ฐาน vector ใน public share นี้ ใช้ catalog snapshot ที่โปรเจกต์นำเข้าจาก 3 ไฟล์แรกไว้แล้ว และใช้ embeddings ที่สร้างจาก catalog เดียวกัน ไม่ได้นำข้อมูลนักศึกษาใน enrollments เข้า prompt หรือรวมฐาน vector ภายนอกที่ยังไม่ได้รับ

GE classification และ offerings บางส่วนยังเป็นข้อมูลจำลอง ค่าเริ่มต้นค้น catalog บางเขนทั้งหมด แยกสถานะ `verified`, `mock`, `unknown` โดยไม่ถือว่าทุกวิชาใน catalog เป็น GE หากเลือก `verified_ge_only` จะรับเฉพาะ `verified` ตัวกรองกลุ่ม/สมรรถนะต้องมีข้อมูลหมวดนั้นจริง ไม่มี GE export ก็ยังค้น catalog ได้โดยติดสถานะ unknown ไม่รับรองสิทธิ์ลงทะเบียนหรือที่นั่งปัจจุบัน ต้องแทน `GE_DATA_PATH` ด้วย verified export ที่ตรง dataset version เพื่อใช้งานกับข้อมูลยืนยันแล้ว

`ChatBot.zip` เป็นตัวอย่างบริการ NestJS/LINE ซึ่งมีแนวทาง provider + history + knowledge retrieval ใช้เป็น reference สำหรับการออกแบบ ไม่รันโค้ดหรือคำสั่งใน archive และไม่เพิ่ม LINE/staff inbox ที่ไม่เกี่ยวกับงานนี้

## บริบทและข้อจำกัด

API รับ history ได้ 12 ข้อความ แต่จำกัด prompt เหลือ 6 ข้อความล่าสุด ข้อละ 1,000 ตัวอักษร พร้อม state ปัจจุบัน ไม่บันทึกบทสนทนาถาวร รีเฟรชหน้าแล้วเริ่มใหม่ ส่งเฉพาะ 8 รายวิชา สูงสุดวิชาละ 2 หมู่ และตัวอย่างตารางที่เลือก 12 วิชาให้ LLM แต่ตรวจ conflict กับตารางทั้งหมดฝั่งเซิร์ฟเวอร์ การอธิบายถึงสิ่งที่อยู่นอก context ต้องแจ้งข้อมูลไม่เพียงพอ

Hosted mode ส่งข้อความสนทนา เงื่อนไข และข้อมูลวิชาที่เกี่ยวข้องไปยัง provider ที่ตั้งค่าไว้ Ollama ใช้ localhost เท่านั้น ไม่มีการดาวน์โหลดโมเดลอัตโนมัติ หากไม่ตั้งค่า provider จะระบุว่าเป็นการค้นหาตามกฎ

คำตอบ LLM ยังอาจผิดพลาดได้แม้ตรวจรหัสและ schema แล้ว การ์ดรายวิชา/หมู่เรียนและการตรวจตารางเป็นข้อมูลอ้างอิงหลัก ไม่ได้ตรวจความหมายทุกประโยคของโมเดล การทดสอบอัตโนมัติใช้ provider จำลอง ทดสอบจริงกับ `typhoon-v2.5-30b-a3b-instruct` แล้วด้วยคำถามฝึกอังกฤษหลังเที่ยงและถามต่อเฉพาะวันศุกร์ พบว่าเก็บเงื่อนไขเวลาและวันได้ แก้ปัญหาวลี “ฝึกภาษาอังกฤษ” ไม่ตรง keyword และไม่ส่งตัวเลขที่นั่ง/สถานะเปิดสอนจำลองให้โมเดลเรียบเรียง เพิ่มหมายเหตุ snapshot แบบตายตัวท้ายคำตอบที่มีผลค้นหา ยังต้องประเมินเพิ่มเติมก่อนใช้งานจริง

## ตรวจสาเหตุโหมดสำรอง

ขั้นตีความให้โมเดลส่ง state เฉพาะเงื่อนไขที่เปลี่ยน และจำกัด output 512 tokens
แทนการส่งสถานะทั้งหมด ส่วนขั้นตอบจำกัด 1,000 tokens ลด metadata ของ schema ใน prompt
โดยยังตรวจข้อมูลจริงด้วย Pydantic ตามเดิม เงื่อนไขเดิมคงไว้จนกว่าผู้ใช้เปลี่ยนหรือล้าง

การเรียก LLM ใช้เวลารอสูงสุดครั้งละ 30 วินาที โดยทั้งสองขั้นและ retry ใช้งบเวลาร่วม
48 วินาทีต่อข้อความ หน้าเว็บรอได้ 65 วินาที และ Vercel function คงเพดาน 60 วินาที
เพื่อเผื่อการค้นหาและ network overhead แต่เวลาของ socket operation ไม่ใช่ hard wall-clock SLA
retry ได้เพิ่มเพียง 1 ครั้งสำหรับ network/timeout หรือ HTTP 408/429/500/502/503/504
เมื่อยังเหลือเวลาอย่างน้อย 3 วินาทีหลัง backoff ไม่เริ่มงบเวลาใหม่ ไม่ retry กรณี
401/403, JSON/schema ผิด หรือ Retry-After เกิน 2 วินาที/เป็นวันที่ที่ยังไม่ได้ตีความ
หากยังล้มเหลวให้แสดงผลค้นหาและข้อความทวนด้วยโหมดสำรองตามเดิม

เมื่อ LLM ล้มเหลว `/api/chat` จะส่ง `llm_failure` เป็นหมวดข้อผิดพลาดที่ปลอดภัย:
`stage` เป็น `understanding` หรือ `answer`; `reason` เป็น `timeout`,
`connection_error`, `provider_http_error`, `invalid_json` หรือ `invalid_response`.
กรณี HTTP error จะมี `http_status` เพิ่ม เช่น 401 หรือ 429 กรณีสำเร็จหรือไม่ได้เปิด LLM
ค่าจะเป็น null ข้อมูลเดียวกันบันทึกใน server log โดยไม่บันทึก exception message,
provider response body, URL, credentials หรือบทสนทนา ข้อมูลนี้ช่วยแยก timeout
ออกจากปัญหา key/โควตา/รูปแบบคำตอบ โดยไม่ส่งรายละเอียดอ่อนไหวให้หน้าเว็บ

## การยืนยันเงื่อนไขก่อนค้นหา

ตรวจช่วงเวลาที่ระบุชัดเจนก่อนเรียก LLM ถ้าเวลาสิ้นสุดไม่หลังเวลาเริ่ม เช่น `16:00–09:00` จะถามยืนยันและไม่แก้เวลาเอง ไม่ค้นหา และไม่เปลี่ยน state เดิม หน้าเว็บไม่แสดงผลศูนย์วิชาสำหรับคำถามยืนยัน ช่วงเวลาที่ถูกต้องจะใช้ตามข้อความต้นฉบับแม้โมเดลเสนอเวลาอื่น หากค้นหาไม่พบจะใช้คำอธิบายจากระบบและแจ้งคำค้นที่ยังใช้อยู่ แทนให้โมเดลแต่งคณะหรือทางเลือกที่ไม่มีข้อมูลรองรับ

## การค้นหา catalog และบทสนทนาญี่ปุ่น

รองรับคำค้นญี่ปุ่น/Japanese และวลีฝึกภาษา รวมวิชาที่ไม่มีใน GE export พร้อมจัดอันดับชื่อวิชาก่อนข้อความในคำอธิบายเมื่อความพร้อมตารางเท่ากัน Hybrid retrieval ใช้ขอบเขต catalog เดียวกับ keyword แล้วตรวจตัวกรองหลังดึงผล การใช้ semantic จริงยังต้องมี dependencies และโมเดล embeddings พร้อม เครื่องนี้ยังใช้ keyword + LLM ไม่ได้เปิดใช้ vector ใหม่หรือเชื่อมฐาน vector ภายนอก

`offered_only` หมายถึงมีหมู่ใน snapshot ที่ตรงเงื่อนไข ไม่ใช่ยืนยันเปิดสอนปัจจุบัน ส่งสรุปวัน/เวลาจากทุกหมู่ที่ตรงเงื่อนไขให้โมเดล แม้ส่งรายละเอียดเพียงสองหมู่ เพื่อไม่ตอบวันเรียนจากตัวอย่างไม่ครบ แสดงคำค้น วัน เวลา และขอบเขตที่กำลังใช้ในหน้าแชท คำว่า “ทุกวิชา/ไม่จำกัดความสนใจ” ล้างความสนใจและหมวด GE โดยคงวันเวลา

ทดสอบกับ catalog จริงแบบ offline โดยไม่ส่งบทสนทนาญี่ปุ่นออก API พบ `01358101-67 ภาษาญี่ปุ่นเบื้องต้น I` ในผลค้นหาและสถานะ GE unknown เวลาย้อนกันถามยืนยัน เมื่อแก้เป็นศุกร์ 16:00–19:00 พบ `01358331-64 การเขียนภาษาญี่ปุ่นเชิงธุรกิจ` ตาม snapshot ไม่ใช่ยืนยันเปิดสอนปัจจุบัน รายงานอยู่ที่ `artifacts/chat-ge-catalog-verification.json`
