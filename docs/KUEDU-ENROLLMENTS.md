# ดึงรายวิชาที่นิสิตลงทะเบียนจาก KU-EDU

หน้า `/enrollments` เรียก backend ของ KU-PAS และแสดงรหัสวิชา ชื่อวิชา สถานะ ผู้สอน และเวลาเรียนจาก KU-EDU ใช้ได้ทั้ง local และ Vercel demo โดยไม่ต้องเปิดบัญชี SQLite บน Vercel มีลิงก์จากหน้าแรกและหน้าจัดตาราง

## ตั้งค่า server

ตั้ง environment variables ต่อไปนี้ใน Vercel Project Settings → Environment Variables แล้ว redeploy (local ให้ export ก่อนเปิด uvicorn; แอปไม่ได้อ่าน `.env` อัตโนมัติ):

- `KUEDU_USERNAME`: บัญชีบริการที่มีสิทธิ์เรียก KU-EDU
- `KUEDU_PASSWORD`: รหัสผ่านบัญชีบริการ
- `KUEDU_STUDENT_ACCESS`: JSON ของสิทธิ์นิสิตตามขั้นตอนด้านล่าง

ทุกค่าเป็น server-only ห้ามใช้ชื่อขึ้นต้น `VITE_` หรือ commit ค่าจริงลง Git ถ้าไม่มีค่าครบหรือรูปแบบสิทธิ์ผิด ระบบปิดการดึงข้อมูลไว้ แต่ค้น catalog และแชทยังใช้ได้ `/api/metadata` บอกสถานะ `enrollment_enabled` โดยไม่เปิดเผยรายชื่อนิสิต

## ออกรหัสเข้าถึงสำหรับกลุ่มทดลอง

หลังตรวจสอบตัวตนและสิทธิ์ของนิสิตแล้ว ให้ผู้ดูแลรันจาก root ของ repository:

```sh
python backend/issue_enrollment_access.py STUDENT_CODE --days 7
```

แทน `STUDENT_CODE` ด้วยรหัสนิสิต 10 หลัก คำสั่งสร้างรหัสสุ่ม 256 บิตและ JSON ตัวอย่างโครงสร้าง:

```json
{
  "<SHA-256 ของรหัสเข้าถึง 64 ตัวอักษร>": {
    "student_code": "<รหัสนิสิต 10 หลัก>",
    "expires_at": "2026-11-26T12:00:00+00:00"
  }
}
```

ส่ง **รหัสเข้าถึงต้นฉบับ** ให้นิสิตเจ้าของข้อมูลเป็นการส่วนตัว นำเฉพาะ JSON ที่มี hash ไปใส่ `KUEDU_STUDENT_ACCESS` รวม entries ไว้ใน object เดียวเมื่อต้องการเพิ่มหลายคน ห้ามเขียนทับ entries ของคนเดิมโดยไม่ตั้งใจ ค่าเริ่มต้นหมดอายุใน 7 วัน กำหนดได้ 1–30 วัน

ผู้ถือรหัสเข้าถึงสามารถอ่านข้อมูลของนิสิตที่ผูกไว้ได้จนหมดอายุ จึงต้องแจกเฉพาะเจ้าของข้อมูล รหัสนี้เป็นสิทธิ์ของกลุ่มทดลอง ไม่ใช่การยืนยันตัวตนผ่าน SSO หากต้องเพิกถอน ให้ลบ entry แล้ว redeploy; ถ้าต้องเปลี่ยนรหัส ให้ออกใหม่และลบ hash เดิมด้วย

## ใช้งาน

1. เปิด `/enrollments` หรือกด “รายวิชาที่ลงทะเบียน” ที่หน้าแรก
2. กรอกรหัสเข้าถึงที่ได้รับ เลือก **ปีการศึกษา พ.ศ.** เช่น `2568` และภาคเรียน `2` (ไม่มีการเดาปีหรือภาคปัจจุบัน)
3. กด “ดึงรายวิชาที่ลงทะเบียน” เพื่ออ่านผลลัพธ์
4. เลือกรายวิชาแล้วกด “นำวิชาที่เลือกไปจัดตาราง” เพื่อแสดงเวลาเรียนจาก API ใน `/timetable` โดยเลือกสถานะ A ไว้เริ่มต้น ให้ตรวจสอบสถานะอื่นก่อนเลือกเพิ่ม
5. ตารางที่นำเข้าเก็บใน sessionStorage ของเซสชันเบราว์เซอร์นี้ รีเฟรชแล้วยังอยู่ ไม่เก็บรหัสเข้าถึงหรือข้อมูลผู้สอน กดล้างตารางหรือล้างข้อมูลส่วนตัวเมื่อเสร็จ

API ภายใน (บน Vercel มี prefix `/api`):

```http
POST /api/enrollments/semester
Content-Type: application/json
X-Enrollment-Key: <รหัสเข้าถึงเฉพาะนิสิต>
```

```json
{"academic_year": 2568, "semester": 2}
```

backend หา `student_code` จากสิทธิ์ที่ตั้งไว้ รับเฉพาะปี พ.ศ. 2500–2700 และภาค 1–3 ไม่ยอมรับ `student_code` จากผู้เรียก จากนั้นขอ token ที่ `/kuedu/api/token/pair` และเรียก `/kuedu/api/std/enrollment/semester` ผ่าน HTTPS โดยตรง มี timeout, จำกัดขนาด response, ไม่ตาม redirect และไม่ส่ง credentials/token กลับ frontend เก็บเฉพาะ token ในหน่วยความจำ ต่ออายุผ่าน `/token/refresh` ก่อนหมดอายุหรือเมื่อได้รับ 401 และลองขอ token ใหม่หาก refresh ใช้ไม่ได้ บน serverless แต่ละ instance อาจต้องขอ token ใหม่เอง

ผลสำเร็จมี `academic_year`, `semester`, `source: KU-EDU` และ `courses` ซึ่งเก็บข้อมูลตามรูปแบบ upstream (รวม `instrs` และ `schedules`) ไม่ส่งรหัสนิสิตหรือ token กลับไป ผล `[]` แสดงว่าไม่มีรายการตามเงื่อนไข ไม่ถูกตีความเป็นข้อผิดพลาดของบริการ

Response สำหรับเส้นนี้ทั้งหมดตั้ง `Cache-Control: no-store` ไม่บันทึก request body/header หรือข้อมูลรายวิชาใน log ของแอป การตั้งค่า logging ภายนอก เช่น reverse proxy ต้องไม่บันทึก `X-Enrollment-Key` หรือ body เช่นกัน

## ขอบเขตข้อมูล

- แสดง `enroll_status` ตามต้นทาง เช่น `A`, `D` ทุกรายการยังแสดงอยู่ โดยเลือก A ไว้เริ่มต้นสำหรับนำเข้า และให้ผู้ใช้ตรวจเลือกสถานะอื่นเอง
- แปลง `schedules` เช่น `Th 16:30-19:30 ...` เป็นเวลาเรียนใน planner โดยตรง ไม่เลือก section ของ snapshot แทน และไม่เดาหน่วยกิตหรือเลขหมู่ ถ้าแปลงเวลาไม่ครบ จะแสดงข้อความเดิมและหยุดการค้นหา GE ตามเวลาว่างจนกว่าผู้ใช้จะตรวจหรือลบวิชานั้น
- ค้น GE โดยส่งเฉพาะช่วงเวลาและรหัสวิชาที่นำเข้าเป็นข้อจำกัดให้ backend แยกจาก catalog refs ไม่ส่งชื่อวิชา ผู้สอน ห้อง หรือรหัสเข้าถึงเข้า LLM/feedback
- ตรวจเวลาชนกับทั้งวิชาจาก KU-EDU และวิชาที่วางแผนไว้ก่อนนำเข้า/เพิ่มแผน ข้อมูล catalog อาจต่างจากภาคจริง และยังไม่ทราบหน่วยกิตรวมของวิชา KU-EDU การวางแผนไม่ใช่การเปลี่ยนการลงทะเบียนจริง
- รหัสเข้าถึงผิด/หมดอายุ: 403; ยังไม่ตั้งค่า: 503; upstream ผิดพลาด/รูปแบบผิด: 502; timeout: 504 ข้อผิดพลาดไม่เปิดเผยข้อมูลดิบของ upstream

## ตรวจหลัง deploy

- ตั้งค่า server ทั้งสามค่า ออกรหัสเฉพาะนิสิตผู้ทดสอบ แล้วตรวจ `enrollment_enabled: true`
- เปิด `/enrollments` โดยตรงและจากหน้าแรก ทดสอบปี พ.ศ./ภาคที่ยืนยันว่ามีข้อมูล
- ตรวจรหัสวิชา ผู้สอน เวลา และสถานะเทียบ Swagger ด้วยนิสิต/ภาคเดียวกัน
- เปลี่ยนปี/ภาคแล้วผลเดิมต้องหาย; ทดลองภาคที่ไม่มีข้อมูล และรหัสผิด/หมดอายุ
- ล้างข้อมูลระหว่างโหลดหรือออกจากหน้า แล้วต้องไม่แสดงผลลัพธ์ของคำขอก่อนหน้า
- ผู้ใช้ส่ง `student_code` เพิ่มใน body ต้องถูกปฏิเสธ และรหัสหนึ่งต้องไม่ดึงข้อมูลของนิสิตอีกคนได้

Automated tests ใช้ข้อมูลสังเคราะห์และ mock upstream ครอบคลุมการผูกสิทธิ์ ปี พ.ศ. การต่ออายุ token ข้อผิดพลาด และการล้างข้อมูลส่วนตัว ต้องทดสอบบน Vercel กับ credentials และสิทธิ์จริงอีกครั้งก่อนแจกกลุ่มทดลอง
